# 슈의 라면 가게 POS

3학년 4반 축제 부스용 POS 웹앱. `index.html` 하나로 동작합니다.

## 바로 써 보기 (로컬 모드)
`CONFIG.firebase.apiKey`가 비어 있으면 **로컬 모드**로 동작합니다.
같은 기기의 여러 탭끼리만 동기화되므로 연습·화면 확인용입니다.

```bash
python -m http.server 8304
```
브라우저에서 `http://localhost:8304` 접속 → 탭마다 역할(결제/조리대/호출/설정·정산)을 골라 확인.

## 실제 운영 (기존 Firebase 프로젝트에 앱 추가 + GitHub Pages)

### 기존 앱을 보호하는 장치
| 위험 | 이 앱의 대응 |
|---|---|
| 컬렉션 이름 충돌 (`orders`, `settings` 같은 흔한 이름) | 모든 데이터를 `ramen304_pos/festival-2026/…` 아래에만 저장 |
| "데이터 초기화"가 다른 앱 데이터 삭제 | 초기화도 위 경로 안에서만 동작 |
| 같은 도메인(○○.github.io)의 다른 앱과 오프라인 캐시(IndexedDB) 충돌 | Firebase 인스턴스 이름을 `ramen304-pos`로 분리 → 캐시 이름도 분리 |
| 보안 규칙 교체로 기존 앱 접근 차단 | 규칙을 **덮어쓰지 않고 한 블록만 추가** (아래 3번) |
| 색인·인증 설정 변경 | 복합 색인 불필요, 로그인/익명 인증 사용 안 함 (설정 변경 없음) |

### 설정 순서
1. **이름 충돌 확인** — Firebase 콘솔 → Firestore Database → 데이터 탭에서 최상위에 `ramen304_pos` 컬렉션이 **없는지** 확인.
   이미 있다면 `index.html`의 `CONFIG.dataRoot`를 다른 이름으로 바꾸고, 아래 규칙의 이름도 똑같이 바꾸세요.
2. **웹 앱 추가** — 프로젝트 설정 → 일반 → 내 앱 → `</>` (웹 앱 추가), 이름 예: `ramen-pos`. Firebase Hosting 체크는 **하지 않음**.
   나오는 `firebaseConfig` 값을 `index.html` 상단 `CONFIG.firebase`에 붙여넣기.
3. **보안 규칙에 블록 추가 (기존 내용은 그대로 두기!)** — Firestore Database → 규칙 탭.
   기존 규칙의 `match /databases/{database}/documents {` 안쪽, 닫는 `}` 바로 위에 아래 블록**만** 붙여넣고 게시:

   ```
       // ---- 슈의 라면 가게 POS (3-4) ----
       match /ramen304_pos/{eventId}/{collection}/{docId} {
         allow read, write: if collection in ['menus', 'orders', 'adjustments', 'counters', 'settings'];
       }
   ```
   - Firestore 규칙은 "하나라도 허용하면 허용"이므로, 이 블록을 추가해도 **기존 앱의 규칙은 바뀌지 않습니다.**
   - 게시 전 규칙 편집기 오른쪽 위 **규칙 플레이그라운드**로 기존 앱 경로 읽기/쓰기가 그대로인지 확인해 보면 안전합니다.
   - 규칙 탭에서 이전 버전으로 언제든 되돌릴 수 있습니다.
   - ⚠️ `firebase deploy` 로 규칙을 배포하는 기존 앱이 있다면, 그 프로젝트의 `firestore.rules` 파일에도 같은 블록을 넣어야 다음 배포 때 지워지지 않습니다.
4. **(해당 시) API 키 제한** — Google Cloud 콘솔에서 브라우저 키에 HTTP 리퍼러 제한이 걸려 있다면 `https://<GitHub아이디>.github.io/*`를 **추가**(기존 항목 삭제 금지).
5. **(해당 시) App Check** — 프로젝트에서 Firestore App Check를 "적용"으로 켜 두었다면 이 앱 요청이 거부됩니다. 기존 앱에 영향 없게 끄지 말고 알려 주세요(대응 방법 별도 안내).
6. GitHub 저장소에 `index.html` 업로드 → Settings → Pages → `main` 브랜치 배포
7. 설정·정산 → 설정 탭 아래 "저장 위치"가 `프로젝트ID / (default) / ramen304_pos/festival-2026`인지 확인
8. 메뉴·가격·초기 수량 입력 → 리허설 → **데이터 초기화** → 운영 시작

> ⚠️ 로그인 없이 운영하므로 앱 주소와 설정값을 아는 사람은 `ramen304_pos` 경로를 읽고 쓸 수 있습니다(다른 앱 경로는 해당 없음).
> 축제가 끝나면 CSV를 받은 뒤 추가한 블록의 규칙을 `allow read: if true; allow write: if false;` 또는 `if false;`로 바꾸세요.

### 무료 한도 (Spark 요금제는 기존 앱과 공유)
- 하루 읽기 5만 / 쓰기 2만 건. 주문 500건 · 기기 5대 기준 대략 읽기 1~2만 · 쓰기 3천 건 수준이라 여유가 있지만,
  기존 앱 사용량이 많다면 축제 당일 Firebase 콘솔 → 사용량 탭을 한 번 확인하세요.
- 내년 축제는 `CONFIG.eventId`만 바꾸면 이전 데이터와 섞이지 않고 새로 시작합니다.

## 기기 배치
| 기기 | 역할 |
|---|---|
| 크롬북 1 | 결제 1 (주문번호 1~100 → 다 쓰면 201~300 → 401~500 …) |
| 크롬북 2 | 결제 2 (주문번호 101~200 → 다 쓰면 301~400 → 501~600 …) |
| 크롬북 1대 | 조리대 |
| 모니터 1대 | 호출 (시작할 때 화면 한 번 터치 → 소리 허용 + 전체화면) |
| 관리자 기기 | 설정·정산 |

## 참고
- 주문번호 발번·재고 확인·주문 취소는 Firestore 트랜잭션으로 처리해 두 대가 동시에 결제해도 번호가 겹치지 않습니다.
- 트랜잭션은 **인터넷 연결이 필요**합니다. 연결이 끊기면 결제 시 오류 안내가 나오며, 화면은 캐시로 유지되다가 복구 시 자동 동기화됩니다. 와이파이가 불안정하면 휴대폰 핫스팟을 예비로 준비하세요.
- 호출 화면 음성은 기기에 설치된 한국어 음성을 사용합니다. 크롬북은 기본 제공됩니다. 설정 탭의 "호출 테스트"로 미리 확인하세요.
- 학교 화폐 단위가 '원'이 아니면 `CONFIG.currencyUnit`, 빠른 입력 금액은 설정 탭에서 바꿀 수 있습니다.
